1. Principios y Paradigmas de Bases de Datos

Durante las sesiones revisamos los conceptos fundamentales para entender cómo se estructuran y almacenan los datos de manera eficiente. Comprendí las diferencias clave entre los dos grandes enfoques del mercado:

Bases de Datos Relacionales (SQL)

Organizan la información en tablas compuestas por filas y columnas bien estructuradas. Se caracterizan por mantener un esquema rígido y asegurar la consistencia mediante relaciones directas y claves primarias.

  • Ejemplos vistos: PostgreSQL, MySQL.
  • Enfoque: Estructura previa definida con lenguaje DDL.

Bases de Datos No Relacionales (NoSQL)

Diseñadas para trabajar con estructuras flexibles o datos semiestructurados (como documentos JSON, clave-valor o grafos). Permiten almacenar información sin necesidad de definir un esquema fijo previo.

  • Ejemplos destacados: MongoDB, Redis.
  • Enfoque: Escalabilidad horizontal y flexibilidad de datos.

2. Práctica: Manejo de DBeaver y Creación de Tablas en PostgreSQL

Puse en práctica lo aprendido conectándome a PostgreSQL desde el entorno gráfico de DBeaver. Escribí los scripts SQL básicos para crear una base de datos y construir tablas asignando sus respectivos tipos de datos y restricciones clave (PRIMARY KEY, NOT NULL, UNIQUE).

Script SQL — DBeaver (PostgreSQL) ddl_inicial.sql 
-- Creación de la base de datos para la práctica
CREATE DATABASE tienda_escolar;

-- Creación de la tabla de Categorías
CREATE TABLE categorias (
    id_categoria SERIAL PRIMARY KEY,
    nombre VARCHAR(50) NOT NULL UNIQUE
);

-- Creación de la tabla de Productos
CREATE TABLE productos (
    id_producto SERIAL PRIMARY KEY,
    nombre VARCHAR(100) NOT NULL,
    precio NUMERIC(8, 2) NOT NULL CHECK (precio >= 0),
    stock INT DEFAULT 0
);
TEMÁTICA DE PROFUNDIZACIÓN

Relación entre Tablas mediante Claves Foráneas (Foreign Keys)

Para profundizar más allá de la creación de tablas individuales, investigué cómo conectar dos entidades mediante llaves foráneas (FOREIGN KEY). Esto permite mantener la integridad referencial de los datos y evitar registros huérfanos en el sistema. 

-- Vinculación de Productos con Categorías (Relación 1:N)
ALTER TABLE productos 
ADD COLUMN id_categoria INT,
ADD CONSTRAINT fk_categoria_producto 
FOREIGN KEY (id_categoria) REFERENCES categorias(id_categoria)
ON DELETE SET NULL;

-- Inserción de prueba para verificar la relación
INSERT INTO categorias (nombre) VALUES ('Papelería');

INSERT INTO productos (nombre, precio, stock, id_categoria) 
VALUES ('Cuaderno Profesional 100 Hojas', 35.50, 50, 1);
